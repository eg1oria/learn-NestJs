## Зачем это в реальной жизни

Задачи приходят на человеческом языке: «пользователь должен иметь возможность вернуть книгу». Бэкендер переводит это в контракт API: метод, путь, статус, тело. Если API спроектирован хорошо, фронтендер угадает адрес эндпоинта, даже не открывая документацию.

## Что сделать

Предметная область: **городская библиотека**. Есть книги (`books`), читатели (`readers`) и выдачи (`loans`). Выдача означает «книга X сейчас у читателя Y».

1. Переведи 10 пользовательских историй в REST. Для каждой укажи **метод**, **путь**, **статус успешного ответа** и **есть ли тело у запроса**:
   1. Показать все книги.
   2. Показать книгу с id 42.
   3. Найти книги автора «Толстой».
   4. Добавить новую книгу.
   5. Исправить год издания у книги 42.
   6. Удалить книгу 42.
   7. Показать все выдачи читателя 7.
   8. Выдать книгу 42 читателю 7.
   9. Вернуть книгу (закрыть выдачу 15).
   10. Показать вторую страницу списка книг, по 20 штук на странице.
2. Опиши одну книгу в JSON: `id`, `title`, `authors` (массив), `year`, `available` (булево) и `publisher` (объект с `name` и `city` или `null`, если издатель неизвестен). Сохрани в `learning/notes/0.3-book.json`.
3. Назови 3 отличия JSON от литерала объекта в JavaScript.
4. Ответы на пункты 1 и 3 запиши в `learning/notes/0.3.md`. Удобнее всего таблицей.

## Критерии приёмки

- [ ] Переведены все 10 историй.
- [ ] В путях существительные во множественном числе (`/books`, а не `/getBook`), без глаголов.
- [ ] Метод соответствует действию: чтение, создание, частичное изменение, удаление.
- [ ] Статусы осмысленные: создание даёт не `200`, а...? (подумай сам).
- [ ] `0.3-book.json` — валидный JSON (проверка ниже).
- [ ] Названы 3 отличия JSON от JS-объекта.

## Как проверить самому

Проверить валидность JSON можно силами Node.js, запусти из корня репозитория:

```bash
node -e "console.log(JSON.parse(require('fs').readFileSync('learning/notes/0.3-book.json', 'utf8')))"
```

Если всё хорошо, увидишь объект. Если нет, получишь `SyntaxError` с указанием позиции ошибки.

## Автотесты

Автотеста нет: это задание на проектирование, его проверяет наставник.

## Подсказки

### Уровень 1 — намёк

Путь отвечает на вопрос «**что**» (ресурс), а метод — на вопрос «**что с ним сделать**». Фильтры и страницы — это не новые ресурсы, а параметры уже существующего.

### Уровень 2 — направление

Фильтры и пагинация живут в query string: `?author=...`, `?page=...&limit=...`. «Выдачи читателя 7» можно выразить вложенным путём `/readers/7/...`. «Выдать книгу» значит **создать** новую выдачу.

### Уровень 3 — почти решение

Пример для другой истории: «показать все отзывы к книге 42» → `GET /books/42/reviews`, ответ `200`, тела у запроса нет. История 8 — это `POST` на коллекцию выдач, а в теле указано, кому и какую книгу выдают. История 9 — это частичное изменение выдачи (её закрытие), а не удаление.
