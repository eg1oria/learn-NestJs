## Зачем это в реальной жизни

Как фронтендер ты отправлял запросы каждый день, просто не смотрел на них. Бэкендер первым делом открывает вкладку Network или логи и смотрит, какой запрос пришёл на самом деле. Догадки о том, что «вроде бы отправилось», при отладке не помогают.

## Что сделать

1. Открой любой сайт (например, `github.com` или свой проект на Next.js), затем DevTools (`Cmd+Option+I` на Mac, `F12` на Windows) → вкладка **Network**, и обнови страницу.
2. Выбери **три запроса разных типов**: сам HTML-документ, запрос к API, который вернул JSON (фильтр Fetch/XHR), и картинку или скрипт.
3. Для каждого запиши:
   - метод (method);
   - полный URL;
   - хост (host) и порт (port). Если порт в URL не указан, напиши, какой подразумевается и почему;
   - статус ответа (status code);
   - `Content-Type` ответа;
   - кто здесь клиент и кто сервер.
4. Ответь своими словами:
   - Что покажет браузер, если открыть `http://localhost:3000`, когда бэкенд **не** запущен? Попробуй на практике. Кто именно «отказал» в соединении, если на этом порту никого нет?
   - Почему фронтенд и бэкенд не могут одновременно слушать порт `3000` на одном компьютере?
5. Всё запиши в файл `learning/notes/0.1.md`.

## Критерии приёмки

- [ ] Файл `learning/notes/0.1.md` существует.
- [ ] Описаны 3 запроса **разных** типов (документ, JSON-API, статический файл).
- [ ] У каждого запроса заполнены все 6 пунктов.
- [ ] Есть ответы на оба вопроса, своими словами, а не копия из интернета.

## Как проверить самому

Сравни то, что видишь в DevTools, с выводом `curl`. Флаг `-I` запрашивает только заголовки:

```bash
curl -I https://github.com
```

Ожидаемо увидишь что-то вроде:

```http
HTTP/2 200
content-type: text/html; charset=utf-8
server: github.com
```

## Автотесты

Для этого задания автотеста нет: код ты не пишешь, заметки проверяет наставник.

## Подсказки

### Уровень 1 — намёк

В панели Network сверху есть фильтры: **Doc**, **Fetch/XHR**, **Img**, **JS**. Каждый показывает запросы только одного типа.

### Уровень 2 — направление

Кликни по запросу и открой вкладку **Headers**. В блоке **General** есть Request URL, Request Method и Status Code, а в **Response Headers** лежит `content-type`. Стандартные порты такие: у `http` это 80, у `https` это 443.

### Уровень 3 — почти решение

Когда на порту никто не слушает, браузер покажет `ERR_CONNECTION_REFUSED`. Подумай, кто отвечает отказом: бэкенда ведь нет. Ответ отправляет операционная система твоего компьютера, примерно так: «по этому номеру никого нет». С портом `3000` то же самое: один порт может «занять» только одна программа. Это как один номер телефона у одного абонента.

## ⭐ Звёздочка

Найди в Network запрос со статусом **не 200** (например, 304, 301 или 404) и объясни, что этот статус значит и почему сервер ответил именно так.
