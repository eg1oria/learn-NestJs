## Зачем это в реальной жизни

`curl` и `.http`-файлы для бэкендера как отвёртка: так проверяют каждый эндпоинт, пока фронтенда для него ещё нет. А когда что-то сломалось на проде, запрос через `curl` быстрее всего покажет, кто виноват: сервер или клиент.

## Что сделать

Все команды выполняются в терминале (подойдёт терминал VS Code, папка неважна). Если терминал непривычен, сначала прочитай [«Терминал без страха»](/library/terminal). Работаем с тестовым API `https://jsonplaceholder.typicode.com`. Это фальшивый «блог», который честно отвечает на любые запросы.

1. Получи пост с id 1 через `curl -i`, потом тот же запрос через `curl -v`. В выводе `-v` найди: стартовую строку запроса, заголовки запроса (строки с `>`), статусную строку ответа, заголовки ответа (строки с `<`) и тело.
2. Создай пост: `POST /posts` с JSON-телом из полей `title`, `body` и `userId`. Добавь нужный заголовок, чтобы сервер понял, что в теле JSON. Ты должен получить статус `201`.
3. Получи `404`: запроси пост, которого не существует.
4. Установи в VS Code расширение **REST Client** (автор Huachao Mao). Создай файл `backend/requests/0.2.http`, запиши в него все три запроса, раздели их строкой `###` и запусти каждый.
5. В `learning/notes/0.2.md` запиши:
   - для каждого запроса: метод, статус и что пришло в теле;
   - что произойдёт с POST, если **забыть** заголовок `Content-Type`? Попробуй и опиши, что вернул сервер;
   - чем отличаются флаги `-i` и `-v`.

## Критерии приёмки

- [ ] Файл `backend/requests/0.2.http` содержит 3 запроса, и каждый запускается из VS Code.
- [ ] POST возвращает `201`, в ответе есть `id` нового поста.
- [ ] Запрос несуществующего поста возвращает `404`.
- [ ] В заметках разобраны все три запроса и есть ответы на оба вопроса.

## Как проверить самому

```bash
curl -i https://jsonplaceholder.typicode.com/posts/1
```

Ожидаемый ответ (заголовков будет больше):

```http
HTTP/2 200
content-type: application/json; charset=utf-8

{
  "userId": 1,
  "id": 1,
  "title": "sunt aut facere repellat provident ...",
  "body": "quia et suscipit ..."
}
```

## Автотесты

Автотеста нет: ты обращаешься к чужому серверу, а не пишешь свой. Наставник проверит `.http`-файл и заметки. Флаги `curl` собраны в [шпаргалке по HTTP](/library/http-cheatsheet).

## Подсказки

### Уровень 1 — намёк

У `curl` есть флаги: `-X` задаёт метод, `-H` добавляет заголовок, `-d` передаёт тело. Если указать `-d`, `curl` сам выберет метод POST.

### Уровень 2 — направление

Заголовок, который говорит серверу «в теле JSON», называется `Content-Type`, а его значение `application/json`. В `.http`-файле запрос выглядит так: первая строка `МЕТОД URL`, потом заголовки, потом **пустая строка** и тело.

### Уровень 3 — почти решение

Заготовка для `.http`-файла, адреса и тело допиши сам:

```http
### Получить пост
GET https://jsonplaceholder.typicode.com/...

### Создать пост
POST https://jsonplaceholder.typicode.com/...
Content-Type: ...

{ ... }
```

## ⭐ Звёздочка

Добавь четвёртый запрос со строкой запроса (query string): получи только посты пользователя 1 (`?userId=1`) и посчитай, сколько их пришло. Объясни в заметках, чем параметр в пути (`/posts/1`) отличается от параметра в query (`/posts?userId=1`) и когда что используют.
