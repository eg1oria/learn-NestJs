## Зачем это в реальной жизни

В Nest всё держится на трёх вещах из TypeScript: на **классах** (из них сделаны контроллеры, сервисы и модули), на **async/await** (каждый поход в базу или в чужой API асинхронный) и на **декораторах**. Кто путается в `Promise`, тот потом пишет сервер, который отвечает раньше, чем база вернула данные.

## Что сделать

Создай файл `backend/src/playground/tavern.ts`. Это песочница, к Гильдии мы её не подключаем. В файле опиши и экспортируй класс `Tavern`:

1. Конструктор принимает `name: string` и `menu: Record<string, number>`, где меню хранит пары «блюдо → цена в золотых». Сохрани их через **параметры-свойства** (parameter properties) `private readonly`, без отдельного объявления полей и присваиваний в теле конструктора.
2. `getName(): string` возвращает название таверны.
3. `order(dish: string): Promise<string>` — асинхронный метод:
   - «готовит» блюдо **100 мс**, то есть ждёт, не блокируя всё остальное;
   - возвращает строку `"<блюдо> подано! С вас <цена> золотых"`, например `"эль подано! С вас 5 золотых"`;
   - если блюда нет в меню, промис **отклоняется** (reject) с `Error`, в тексте которого есть название блюда.
4. `getEarnings(): number` возвращает сумму всех **успешно** поданных заказов.
5. `orderMany(dishes: string[]): Promise<string[]>` готовит несколько блюд **параллельно**. Ответы приходят в том же порядке, а всё вместе занимает примерно столько же, сколько одно блюдо, а не сумму.
6. Нигде не используй `any`.

## Критерии приёмки

- [ ] `Tavern` экспортируется из `src/playground/tavern.ts`.
- [ ] В конструкторе используются параметры-свойства `private readonly`.
- [ ] `order` ждёт около 100 мс и возвращает строку точно в нужном формате.
- [ ] Неизвестное блюдо даёт отклонённый промис с понятным сообщением.
- [ ] Выручка считается только по успешным заказам.
- [ ] `orderMany` из трёх блюд занимает меньше 250 мс.
- [ ] Тест `1.1` зелёный, `npm run lint` и `npm run build` без ошибок.

## Как проверить самому

Быстрый ручной прогон без тестов (что такое `npx`, рассказано в статье [про npm](/library/npm)). Временно добавь в конец файла код ниже и запусти `npx ts-node src/playground/tavern.ts`:

```ts
const t = new Tavern('Пьяный дракон', { эль: 5 });
t.order('эль').then(console.log); // через ~100 мс: эль подано! С вас 5 золотых
```

Не забудь потом убрать этот код из файла.

## Подсказки

### Уровень 1 — намёк

Конструктор вида `constructor(private readonly x: string) {}` сам создаёт поле `this.x`. А «подождать» в асинхронном коде можно, только завернув `setTimeout` в `Promise`.

### Уровень 2 — направление

Внутри `async`-функции `throw new Error(...)` превращается в отклонённый промис. Для параллельного ожидания нескольких промисов есть `Promise.all`, он принимает **массив промисов**. А массив промисов из массива блюд можно получить через `map`.

### Уровень 3 — почти решение

Помощник для задержки — это функция, которая возвращает `new Promise(resolve => setTimeout(resolve, ms))`. В `order` три шага: проверить, есть ли блюдо в меню (если нет — `throw`), дождаться `delay(100)`, прибавить цену к выручке и вернуть строку. В `orderMany` нужна одна строка с `Promise.all` и `map`. Если писать `await` в цикле `for`, получится последовательно, и тест на скорость упадёт.

## ⭐ Звёздочка

Напиши свой **декоратор метода** `@Measure()` в `src/playground/measure.ts`. Он должен выводить в консоль, сколько миллисекунд занял вызов, например `order took 101ms`. Повесь его на `order`. Так ты своими руками увидишь, что декоратор — это просто функция, которая оборачивает другую функцию.
